================================================================================
Lelam.co — Complete Platform & System Documentation
================================================================================

Lelam.co is a search engine, discovery, and bidding assistance platform
for government and industrial surplus auctions (specifically MSTC eAuctions). 

Because official government portals are difficult to navigate and contain dense 
catalog PDFs, Lelam.co automatically reads these PDFs, parses them into searchable 
listings, runs optical character recognition (OCR) on tables, and provides 
calculation tools to help buyers estimate costs, run market price predictions, 
and assess ROI before bidding.

3. Technology Stack & Core Dependencies
--------------------------------------------------------------------------------

The Lelam.co platform is constructed utilizing a modern, high-performance, and secure technical stack:

Frontend Core & User Interface:
* React 19: Powered by React hooks, providing client-side state management for fast component updates and immediate currency exchanges without page reloads.
* TypeScript: Enforces strong compile-time type safety across database entities and component states.
* Vite: Ultra-fast bundler and development build toolchain.
* Zustand: Lightweight global state manager handling persistent application states such as authentication tokens, watchlist counts, and currency preferences.
* React Router DOM v7: Manages robust declarative routing across different pages and layouts.

UI & Styling System:
* Tailwind CSS v4: Utility-first CSS processing for rapid development of visual styles and responsive grids.
* Ant Design (antd & @ant-design/icons): Provides robust, accessible enterprise design system components, layout panels, and tabular elements.
* Radix UI: Unstyled primitive components for accessible layout structures (Labels, Popovers, Slots).
* Lucide React: Premium, consistent vector icon library representing categories, calculations, and dashboard actions.
* Framer Motion: Custom physics-based animation engine enabling subtle micro-animations and smooth layout transitions.
* Recharts & D3: Data visualization libraries that drive the responsive market price trend graphs and historic commodity charts.

Backend, Database, & Security (BaaS):
* Supabase Service Layer: Orchestrates database connections, file storage, and authentication.
* PostgreSQL Database: High-performance relational database containing profiles, indexed auctions, commodity listings, watchlists, logs, and FAQs.
* Row Level Security (RLS): Enforces server-side PostgreSQL policies, securing company assets, business licenses, and watchlists so users can only access their authorized files.
* Supabase Storage Buckets:
  - auction_documents: Hosts original government catalog PDFs and rendered lot preview images.
  - avatars: Manages profile avatars.

Automation, Crawling, & Heavy Lifters:
* Node.js (tsx / npm run scripts): Backend runtime coordinating cron workers, scrapers, and data pipelines.
* Puppeteer & Puppeteer-Extra: Control headless instances of Google Chrome.
* Puppeteer Stealth Plugin: Modifies headless browser footprints, bypassing basic anti-bot blockers on official government portals.
* pdf-parse: Fast Node utility extracting raw digital text and tabular structures from downloaded catalog PDFs.
* Tesseract.js OCR: Client/Server computer vision library executing Optical Character Recognition on scanned tables, image assets, or blurry catalog sheets.
* @xenova/transformers (all-MiniLM-L6-v2): Local artificial intelligence model generating semantic vector embeddings to power conceptual searches.

6. Technical Architecture & Backend Flow
--------------------------------------------------------------------------------

Lelam.co automates the ingestion of government eAuctions through a multi-stage background collection pipeline.

Flow Diagram:
[ Puppeteer Crawler ]
        │
        ▼ (Finds New Catalogs)
[ Supabase Database (status: 'pending') ]
        │
        ▼ (Polled by Background Asset Worker)
[ Asset Worker Processes PDF ]
        ├─► Converts Pages to Images (for preview & OCR)
        ├─► Reads Text (using pdf-parse)
        ├─► Runs OCR (Tesseract.js for scanned tables)
        ├─► Computes Search Embeddings (@xenova/transformers)
        │
        ▼ (Updates Records)
[ Supabase Storage & PostgreSQL Search Index ]

Collection Pipeline Details:
1. Discovery (Scraper): 
   - A Node.js cron worker launches a Puppeteer Stealth browser instance.
   - It navigates to official listing portals, bypasses basic anti-bot scripts, reads the catalog table list, and detects new auction numbers.
   - It inserts a new row in mstc_auctions with asset_status = 'pending'.
2. Download & Storage:
   - The Asset Worker polls the database for pending rows.
   - It downloads the raw catalog PDF, uploads the original file to the auction_documents bucket inside Supabase Storage, and sets a unique file URL path.
3. OCR & Text Extraction:
   - The worker runs pdf-parse to read embedded text.
   - For pages containing scanned tables, lot details, or photos, the worker converts the PDF pages into JPEG images.
   - It feeds these images to Tesseract.js to perform Optical Character Recognition (OCR), extracting hidden quantity numbers, contact details, and locations.
4. Vector Embedding Generation:
   - Using the @xenova/transformers library (running the all-MiniLM-L6-v2 model), the worker converts parsed item descriptions into high-dimensional vector arrays.
   - These vectors are saved to the database to support semantic search.

ML Estimation Architecture:
The platform runs a lightweight, deterministic prediction algorithm powered by pre-calculated coefficients from a trained linear regression model (scrap_model_metadata.json):
* Equation: Predicted Price = Intercept + Sum(Feature_i * Coefficient_i)
* Grade and Region categories are converted via one-hot encoding offsets stored in coefficients, while numerical components (LME, exchange rates, domestic commodities, construction indicators, season) scale linearly.
* Real-time updates occur via standard React side-effects on input modifications, ensuring instant calculation speeds.

Database Storage Structure:
* Core Relational Tables:
  - mstc_auctions: Holds parsed MSTC catalog entries (numbers, seller, raw material JSON, status, document links).
  - profiles: Stores user account details and role classifications (buyer, seller, admin, superadmin).
  - watchlists: A join table mapping user profiles to saved auctions.
  - market_indices: Stores metal commodities with their current unit costs, keyword mappings, and formulas.
* Storage Buckets:
  - auction_documents: Stores raw catalog PDFs and rendered first-page previews (JPEGs) used in listing cards.
  - avatars: Stores user profile pictures.

7. Simple Explanation of Technical Terms
--------------------------------------------------------------------------------

* Scraping / Crawling: An automated program that visits websites to download catalog sheets.
* OCR (Optical Character Recognition): Reads text inside images or scanned PDFs, making tables searchable.
* Database (Supabase / Postgres): The digital filing cabinet storing user profiles, watchlists, prices, and catalogs.
* Landed Cost: The total price of scrap items after adding transport, labor, and taxes (GST/TCS/customs).
* ROI (Return on Investment): The estimated profit margin you make after subtracting all costs from the market value.
* RLS (Row Level Security): A digital security lock that ensures user A cannot view or edit the documents or watchlists uploaded by user B.
* Vector Embeddings: Numerical representations of text that let search engines understand context (e.g. searching for "cable" matches "wire").
* Linear Regression Model: A mathematical model that makes pricing predictions by finding straight-line relationships between factors (like exchange rates or coal costs) and metal prices.
* Coefficient & Intercept: The starting price baseline (intercept) and the positive or negative impact weight (coefficient) assigned to each predictor factor.
